# 发现栏目 UX 评审

评审日期：2026-10-10。评审角色：UX（用户体验）评审代理。对象为现有 PXID-H5 的推荐、动态、广场及动态详情；目标是在直板、双折叠、三折叠上保持同一任务的能力、阅读层级、操作反馈与连续性，并非把所有设备排成相同列数。

依据：已读取 `AGENTS.md`、视觉规范及当前本地组件；已查看本地实际运行截图 `discover-plaza-running.png`、`discover-dynamic-running.png`、`discover-fold-running.png`。截图位于 `D:\Codex\Projects\2026-09-11\du`，使用本地测试数据。本评审没有真机、软键盘、原生权限弹窗或性能指标的实测，也没有编造评分。本轮实施代理正在针对以下问题修改；本文的问题确认和建议不等同于修改完成后的验收通过。

## 产品结构判断

- 推荐承担内容发现；动态承担按时间、关注关系或距离浏览作者帖子；广场承担同车型、话题、活动的组织入口。结构合理，可继续实施。
- 话题与车型是内容维度，全部/关注/附近是人群及范围维度，应相互独立。无结果、未登录、定位失败应明确解释，不能用其他数据冒充结果。
- 手机点帖子进入详情，大屏点帖子在右栏阅读，这两种入口可以不同，但点赞、收藏、评论、分享、图片预览和正文可读性应相同。
- 保留已经认可的图数规则：1 图头图、2 图并列、3 图 Bento、4 图四宫格、5 图轮播、6/7 图 Bento、8 图轮播、9 图九宫格；不用随机布局增加记忆成本。

## 按优先级处理

### P1：右栏是功能不足的第二种详情

**已确认。** 评审起始版本中 `DiscoverView.vue` 的右栏使用独立简化模板，正文 `.panel__text` 为 14px，作者、时间及评论层级与 `FeedDetailView.vue` 不同；点赞和评论只是静态数字，没有完整的点赞、收藏、评论输入。设备展开后，同一个帖子反而失去互动能力。右栏点赞数字一律价格红，也把统计与选中状态混在一起。

**最小改法：** 为 `FeedDetailView.vue` 增加可选嵌入模式，右栏复用同一详情；默认独立页行为不变。底部互动栏限制在右栏，评论输入按右栏实际位置定位，不覆盖左侧列表。嵌入时不触发关闭根 WebView 的返回逻辑，详情 ID 优先取嵌入参数，保留请求失效保护及既有图片布局。

### P1：同帖在左、右栏同时出现，状态必须同步

**已确认基础风险。** `MomentCard.vue` 的点赞、收藏状态从 `item` 初始化为内部 ref；评审起始版本没有监听后续 `item.isLiked/likes/isFavorited`。只修改父级数据，卡片仍可能保留旧数字或旧图标状态。

**最小改法：** 详情与卡片成功互动后向父级发送同一帖子状态更新；同步推荐列表、动态列表、附近列表及详情快照，卡片监听相应字段。快速切帖时记录操作发起的帖子 ID，迟到结果只更新原帖，不能给新帖点赞或覆盖其评论。失败回滚保留明确提示。

**验收：** 左卡点赞立即映射右栏，右栏点赞/收藏/评论成功也映射左卡；切回原帖仍一致。不能以重新刷新整页作为同步方式。

### P1：折叠姿态变化会丢失当前阅读

**已确认。** 起始版本 `DiscoverView.vue` 的 `onSplitChange` 只更新 `isSplit`；缩到小于 600px 会卸载右栏，却没有把主动阅读的帖子和位置交接到手机详情。左右滚动容器与文档滚动的切换也没有可见内容锚点恢复。

**建议：** 仅用户主动选中或操作右栏后，收起设备才延续到原有完整详情入口；自动默认选中的第一帖不能强迫用户跳页。临时交接帖子 ID、正文阅读位置、轮播索引和未发送评论；返回列表恢复原筛选与可见卡片。跨原生 WebView 的交接不得依赖隔离的 `sessionStorage`，需要复用现有快照式共享存储或桥能力，并标明真机待联调。

### P1：大屏选中帖没有明确反馈

**已确认。** `FeedCard.vue`、`MomentCard.vue` 接收 `onSelect` 后只切换右栏，起始版本没有选中参数和视觉标记。截图中左右内容不同，用户无法从左栏识别正在阅读哪一条。

**最小改法：** 增加可选 `selected` 状态，仅发现页分栏使用；轻品牌边或内描边配合浅底，并添加当前项语义。样式不能改变卡片尺寸、造成列表跳动，也不能遮挡图片。上一/下一条切换时保证新选中的卡片可辨认，必要时最小距离滚入左栏可视区。

### P2：搜索改变了大屏浏览方式

**已确认。** 起始版本搜索结果 `FeedCard` 没有传递 `onSelect`，搜索时右栏被条件隐藏。原本可以并排阅读，搜索后却强制进入独立详情；返回时用户需要重新建立上下文。

**最小改法：** 搜索结果仍可选择右栏，上一/下一条限定在当前结果中，清除搜索后恢复当前栏目。现有搜索只查已加载列表，应在结果说明中明确此范围，不能暗示搜索全部社区。结果数量和空态需三语一致。

### P2：推荐失败没有可操作的解释

**已确认。** `DiscoverView.vue` 在请求异常时写入 `loadErr`，起始推荐模板却未展示错误和重试入口；首次请求和跨栏目懒加载也不全由同一个加载判据控制，容易出现空白或被误认为没有内容。

**最小改法：** 推荐使用自己的实际请求状态区分加载、空内容和请求失败；失败提供局部重试，已有内容保留。广场话题、活动各自展示真实失败与重试，不用演示数据填补错误。

### P2：统一排版需按内容容器，而非整块屏幕宽度

**已确认代码差异，具体窄栏效果需运行验证。** `DiscoverView.vue` 与 `FeaturedView.vue` 的根导航字号已经相同，但未选颜色、下划线尺寸及按钮热区不同；同类边距使用 12/16px 混合。广场 `.topic-grid` 用 viewport 的 900px 断点，不能表达该组件真正获得的宽度。600px 分栏后左栏只有约 300px，不能继续以整屏宽度把局部文字或网格扩大。

**最小改法：** 根导航共用轻量样式令牌，保留全局 56px TopBar；发现、精选现有浅蓝页面背景与搜索风格保持一致。章节标题、正文、次要文字、圆角和间距按语义收敛，主内容使用同一 16px 对齐线。广场在可用宽度足够时横向安排模型/话题与活动区域，在窄屏维持原顺序；不新增空白右栏。网格按真实容器宽度改变列数，不能为了保留更多列把正文缩小。

**颜色补充：** `#4D7CFF` 在白色和品牌浅底上的小字对比度约为 3.72:1 和 3.35:1；时间 `#8b919c` 在白底约为 3.17:1。这是颜色数值计算，不是真机可读性测量。保留品牌主色用于图标、下划线和填充，可为小字号链接与选中文字定义统一的较深蓝文字角色；不要逐组件另挑颜色。推荐话题卡与广场话题入口的类别可共用图标与颜色语义，避免同一话题一处彩虹渐变、另一处蓝色图标导致识别割裂。

### P2：热区、键盘、长文字要一起检查

**已确认。** 起始 `DiscoverFilterBar.vue` 模型选项高度 42px，卡片更多/互动多数 36px，话题标签没有最小热区；模型弹层标注为 listbox，却只实现点击和 Esc，没有方向键选项导航。根标签导航也没有方向键行为。已有 Tab 可横滚，葡语和英文较长时隐藏选项的可发现性需检查。

**最小改法：** 常用触控热区至少 44px，保持紧凑视觉但扩大真实点击区域。菜单展开焦点移到当前项，方向键移动、Enter/Space 选择、Esc 返回触发器；点击外部关闭，必要时限制菜单高度并内部滚动。卡片主阅读入口和作者入口提供可聚焦语义，避免嵌套按钮。模型选择与范围选择必须能在窄栏使用，长话题可换行或省略并保留完整可访问名称，不能以缩字解决。

## 实施后的验证清单

浏览器宽度：375、390、430、600、854、1017、1337px。后三种为 H5 获得的内容宽度，Flutter 的导航 rail 不在 H5 再次扣减。

1. 每个宽度跑相同任务：浏览推荐、切动态范围/车型、进入话题、搜索、读详情、预览图、点赞、收藏、写评论、返回。
2. 确认分栏每栏独立滚动，导航固定在各自栏内，互动栏不覆盖另一栏，末条内容能滚到按钮上方。
3. 连续执行 390 → 854 → 390、600 → 1337 → 430；主动阅读与自动默认选中分开测试，筛选、帖子、读到位置、轮播、草稿均不丢失。
4. 测试 1–9 图，长标题、长作者、长话题、没有图片、视频混合、空列表、失败、迟到请求；所有状态都有真实可操作反馈。
5. 中文、英文、葡文下检查导航、菜单、计数、错误、评论输入和话题页；查看键盘焦点、Esc、方向键，不只断言没有横向溢出。
6. 真机补测：直板、双折叠、三折叠的原生 WebView 交接，登录/定位提示，键盘弹起与关闭，分享及详情返回。浏览器结果不能替代这些原生验证。

评审结论：继续沿用已经认可的产品结构；先修复跨设备的功能与阅读连续性，再收敛颜色、导航和局部间距。无需另换品牌、重写整页或改变 1–9 图布局。

## 本轮实施与复核结果

以下为评审后的实际本地修改，区别于上文起始版本的问题记录。

- 右栏以可选嵌入模式复用 `FeedDetailView.vue`；正文、图片规则、完整评论、点赞、收藏、分享及图片预览使用同一组件。互动栏及评论输入限制在右栏内，左右卡片状态同步，选中卡片有品牌色描边且不改变尺寸。
- 主动阅读时从分栏收起到手机详情，交接当前帖子、阅读滚动位置、轮播页和评论草稿；返回按原帖锚点恢复列表。自动默认预览、换车型后自动选中的帖子不触发强制跳转。滚动交接避开页面转场重置，返回锚点复用原路由滚动机制。
- 根导航、页面背景和选中文字采用共同样式令牌；发现与精选导航使用相同字号和指示器。话题入口共用分类图标与品牌蓝语义，卡片圆角和次要文字颜色收敛。600px 窄分栏推荐使用单列卡片；广场宽屏并排安排车型与话题，活动放下一行；独立宽屏详情限制在 680px 阅读宽度。
- 详情顶栏为两枚操作图标预留空间，长作者使用省略号，保持既有 56px 顶栏及 18px/500 标题规格。模型菜单和根导航支持键盘选择，常用操作扩大触控热区。
- 页面停用时关闭评论输入、预览和弹层，撤销键盘监听并保留未发送草稿。覆盖式键盘按实际高度留出内容滚动空间；调整布局视口时不重复增加键盘高度。
- 为互动及详情加载加入状态版本保护。点赞成功后迟到的详情响应不会回写旧状态；失效的请求也不能重新填入旧缓存。推荐请求失败提供真实错误和局部重试，不用演示列表代替。

修改集中于 `DiscoverView.vue`、`FeedDetailView.vue`、`DiscoverFilterBar.vue`、`DiscoverPlaza.vue`、`FeedCard.vue`、`MomentCard.vue`、`DiscoverTopicCard.vue`；配套修改 `tokens.css`、`i18n/index.js`、`feedReading.js`、`api/feed.js` 和路由滚动交接。`FeaturedView.vue` 只同步导航与背景样式令牌，购买流程及商品内容未改。

已完成：生产构建、后端语法检查、11 项数据与商品回归、40 项浏览器检查，浏览器未报告页面异常。覆盖 375、390、430、600、854、1017、1337px，独立详情与分栏各自的 1–9 图布局，左右点赞/收藏/评论同步、局部搜索、失败重试、方向键与 Esc、长作者顶栏、折叠收起/返回、轮播和草稿，以及旧请求不能覆盖操作或重新污染缓存。
