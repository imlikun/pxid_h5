# PXID 品向智行 ToC 厂商 App — 完整产品功能文档（对标问界 AITO）

> 用途：立项功能完整性体检。对照问界（AITO）汽车厂商 App，评估现有 PRD v1.1（发现/精选/售后）在「功能是否缺失、完整厂商 App 该有哪些」。
> 建立：2026-08-19。对标源：问界 AITO App（华为赋能，130+ 远程控车、官方资讯、车主社区、活动、精选商城、充电地图、维保预约）。
> 参考：PRD-2026-08-18-DISCOVER-MALL-AFTERSALES v1.1 + PXID_H5 项目进度总览（2026-08-19）。

---

## 0. TL;DR（结论）

1. **PRD v1.1 立项定位就不是「完整厂商 App 规格」**，它自己声明只负责「发现 / 精选 / 售后轻前端」三块，其余明确写「由平台 C 已有」「本轮不做」。所以严格说它不是「缺」，是「立项时只切了三分之一」。
2. **但有两处属于 PRD 范围内本该写全却漏了的（用户点名正确）**：
   - **官方发帖 / 删帖**：§4.5 运营后台只有「发布图文 + 上架/下架（OFFLINE 状态）」，缺**物理删除/编辑/撤回/置顶/定时发布/操作审计**的完整内容生命周期。
   - **活动功能**：§4.4 把活动降格为 `content_type=ACTIVITY` 的普通内容标签 + 广场「热门活动」入口，**没有独立的活动运营模块**（创建/配置/报名/有奖互动/数据看板）。问界把活动当「官方活动主阵地」。
3. **其余问界核心能力分两类**：
   - 平台 C 已有（控车/充电/购车/绑车/FAQ）——不该重做，PRD 边界正确；
   - 整个立项没规划的（话题圈子/私聊群聊/积分体系/维保预约/消息中心/分享）——属后续版本，需补进产品路线图。

## 2. 立项缺口分类（对照 PRD v1.1）

| 类别 | 含义 | 包含功能 |
|---|---|---|
| **A. PRD 已覆盖** | 本轮规划内 | 发现推荐/广场/动态、精选浏览/详情/下单、售后门店/工单、平台 D 后台基础（发布/Banner/四宫格/楼层） |
| **B. 平台 C/平台 A 已有（非本轮）** | 边界正确，不重做 | 控车、充电、购车配置/试驾/金融、绑车、FAQ/三包/反馈、工单真相/质保 |
| **C. PRD 范围内漏写（应补 v1.2）** | 用户点名，确属缺失 | **①官方发帖删帖完整闭环 ②活动运营模块** |
| **D. 后续版本未规划（需补路线图）** | 整个立项没提 | 话题/圈子、私聊/群聊、积分体系、维保预约前端、消息中心、分享、设置 |

> 注：PRD §3.2 写明「发现社交（好友/群聊/通讯录）本轮不做」、§4.1「积分账本未启用」——这些是有意推迟（D 类），不是疏漏；但**发帖删帖 + 活动（C 类）是 PRD 本该在「平台 D 运营后台」章节写全却没写的**。

## 3. 用户点名两处缺失 · 规格补丁建议

### 3.1 官方发帖 + 删帖（运营后台内容生命周期）
**现状（PRD §4.5）**：运营账号登录 → 内容列表（筛选/上架下架）→ 发布官方动态（图文）→ Banner 配置 → 四宫格跳转。
数据表 `d_discover_post` status 仅 `DRAFT/PENDING/PUBLISHED/REJECTED/OFFLINE`。

**缺失的运营能力**：
- 编辑已发布内容（改文案/图/车型标签）
- 物理删除 / 强制撤回（不只是 OFFLINE 软下架）
- 置顶 / 取消置顶
- 定时发布 / 撤回定时
- 多图 / 视频媒体管理
- 按 region 批量发布 / 撤回
- 操作日志 / 审计（谁、何时、改了什么）

**建议补丁（v1.2）**：
```sql
-- d_discover_post 增加字段
is_top        TINYINT   DEFAULT 0   -- 置顶
scheduled_at  DATETIME  NULL       -- 定时发布
deleted_at    DATETIME  NULL       -- 物理删除（软删审计）
updated_at    DATETIME  NULL       -- 最后编辑
operator_id   BIGINT    NULL       -- 操作人（运营账号）
-- 运营后台新增按钮：编辑 / 删除 / 置顶 / 定时，并写 d_discover_audit_log
```
接口补：`PUT /discover-api/posts/{id}`（编辑）、`DELETE /discover-api/posts/{id}`（删除）、`POST /discover-api/posts/{id}/top`（置顶）。

### 3.2 活动功能（独立运营模块，对标问界「官方活动主阵地」）
**现状（PRD §4.4）**：活动 = `content_type=ACTIVITY` 的普通帖；广场「热门活动」从 post 表按 type 拉；无报名/有奖/数据。

**缺失的运营能力（问界有）**：
- 活动后台：创建/编辑/配置（时间窗/规则/奖品/报名表单/封面）
- 活动类型：有奖互动 / 打卡 / 征集 / 线下聚会 / 试驾
- 报名 / 参与（userId 报名、名额限制、审核）
- 中奖 / 抽奖 / 发奖
- 活动数据看板（参与人数/转化/分享）
- 活动与内容/商城联动（活动页挂商品/话题入口）

**建议补丁（v1.2）**：
```sql
-- 新增独立活动表（不从 post 表降格）
d_discover_activity
  id, title, cover_urls, rule_text, activity_type   -- OFFICIAL_INTERACTIVE/SIGN_UP/OFFLINE...
  start_at, end_at, status (DRAFT/PUBLISHED/OFFLINE)
  sign_up_limit, sign_up_count, prize_text
  region_code, operator_id, created_at, deleted_at
d_discover_activity_signup   -- 报名记录 member_id / 报名时间 / 状态
d_discover_activity_winner   -- 中奖记录
```
接口：`/discover-api/activities`（列表，广场热门从此拉，不再混 post）、`POST /discover-api/activities/{id}/signup`、`GET /discover-api/activities/{id}/winners`。
运营后台新增「活动管理」页：创建/编辑/下线/报名名单/中奖导出。

## 4. 建议下一步

1. **v1.2 补丁**：把 §3.1（发帖删帖完整闭环）+ §3.2（活动运营模块）补进 PRD 平台 D 运营后台章节，定为 D-MVP1~MVP2 范围。
2. **路线图补 D 类**：话题/圈子、私聊群聊、积分体系、维保预约前端、消息中心、分享——作为后续版本立项，不在本轮但需有规划，避免再次「立项即缺失」。
3. **边界维持**：控车/充电/购车/维保真相继续走平台 C / 平台 A，平台 D 不重做（PRD 边界正确，点赞）。
4. **H5 现状核对**：进度总览显示 H5 当前是八戒 `pxid-feed-server`（SQLite），运营后台实际未建——§3 的补丁需等平台 D 独立后台落地后才能真正生效，当前 H5 无删帖/活动管理入口。
