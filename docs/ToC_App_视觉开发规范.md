# ToC App 视觉开发规范

> 版本：v1.0  
> 适用范围：Flutter ToC App 中国及 Google Play 渠道的全部原生页面  
> 基准：以当前代码实现和已接入的全局主题令牌为准；本文档用于后续 UI 开发、评审和存量页面渐进式收敛。

## 1. 使用原则

### 1.1 设计坐标与适配

- 所有尺寸均使用 Flutter 逻辑像素（dp）；`TextStyle.fontSize` 使用逻辑字号（sp）。
- 页面必须考虑 `SafeArea`、刘海、状态栏、底部手势区和键盘遮挡。
- 页面级横向边距优先取 12、16 或 24；不得在同一页面随意混用多个横向基准。
- 图片必须明确 `fit` 与对齐方式。车辆 Hero 图以 `Alignment.topCenter + BoxFit.cover` 为准，保证顶部主体优先展示，底部允许裁切。
- 多语言文字必须预留扩展能力：按钮、Tab、列表标题优先使用单行省略或既有 `AuthMarqueeText`，避免固定宽度导致换行挤压。

### 1.2 令牌优先

- 新页面优先导入 `package:pxidiot_toc_app/core/core.dart`，使用 `AppColors`、`AppTextStyles`、`AppSpacing`、`AppRadius` 与 `AppTheme`。
- 局部规格确有差异时，优先从全局文字样式 `copyWith` 扩展；禁止重复散落同类色值、字号和圆角。
- 存量页面存在历史硬编码规格。新增或改造时按“色彩 → 间距/圆角 → 字体 → 通用交互”顺序逐步迁移，不要求一次性改动全部页面。

### 1.3 交互与反馈

- 所有卡片、菜单行、图标入口和按钮可点击区域优先使用 `GrayPressable`。
- `GrayPressable` 按下覆盖层为 `#26000000`，悬停/焦点覆盖层为 `#14000000`，点击前保留 100ms 按压态。
- 可点击区域需要与视觉圆角一致地传入 `borderRadius`，避免按压层越出卡片边界。
- 点击触发网络请求的入口必须保留防重复点击锁；加载、Toast、确认弹窗和底部弹层分别复用 `AppLoading`、`AppToast`、`AppDialog`、`AppBottomSheet`。

## 2. 基础视觉令牌

### 2.1 字体

项目当前未配置自定义 `fontFamily`，使用 Flutter/系统默认字体栈。跨页面一致性通过字号、字重、颜色与行数约束保证。

| 语义 | 字号/字重 | 默认颜色 | 推荐场景 |
| --- | --- | --- | --- |
| 页面大标题 `titleLarge` | 20 / w600 | `#111111` | 页面标题、卡片主标题 |
| 正文 `body` | 16 / w400 | `#111111` | 正文、输入内容、主要信息 |
| 主按钮 `buttonPrimary` | 18 / w500 | `#111111` | 大型主操作按钮 |
| 次按钮 `buttonSecondary` | 15 / w500 | `#666666` | 次级按钮、列表操作 |
| 辅助说明 `caption` | 12 / w400 | `#666666` | 标签、单位、时间、提示 |
| 指标值 `metricValue` | 22 / w700 | `#111111` | 电量、里程、统计核心数值 |
| 指标单位 `metricUnit` | 12 / w500 | `#666666` | 核心数值的单位 |
| 底部导航 `bottomNavLabel` | 11 / w400 | 跟随选中态 | 五栏底部导航标签 |

补充使用范围：列表标题通常为 14–16 / w500；AppBar 居中标题通常为 16–18；大数据指标可扩展为 28 或 34；深色页面文字使用白色和不同透明度层级区分主次。

### 2.2 色彩

| 分类 | Token/色值 | 使用规则 |
| --- | --- | --- |
| 品牌主色 | `AppColors.brandPrimary` / `#4D7CFF` | 选中态、强调按钮、进度与关键操作 |
| 常规页面背景 | `AppColors.appBackground` / `#F5F7FA` | 新建浅色常规页面默认背景 |
| 历史浅灰背景 | `AppColors.neutralBackground` / `#F5F5F5` | Mine、设置、FAQ 等存量页面 |
| 服务背景 | `AppColors.serviceBackground` / `#F0F1FB` | 服务首页及服务模块视觉底色 |
| 卡片表面 | `AppColors.surface` / `#FFFFFF` | 卡片、列表分组、白色面板 |
| 主文本 | `AppColors.textPrimary` / `#111111` | 页面标题、正文、重要内容 |
| 次文本 | `AppColors.textSecondary` / `#666666` | 副标题、说明、次级操作 |
| 弱文本 | `AppColors.textTertiary` / `#7F7F7F` | 占位、弱化说明、导航未选中 |
| 默认边框 | `AppColors.border` / `#E5E7EB` | 输入框、轻边界、分隔线 |
| 成功/警告/错误 | `#2E7D32` / `#F57C00` / `#D93025` | Toast、状态提示、错误反馈 |
| 深色背景 | `AppColors.darkBackground` / `#0D0F12` | 购车沉浸页 |
| 认证背景 | `AppColors.authBackground` / `#000000` | 登录及认证沉浸页 |

认证页补充：主文字 `#FFFFFF`、辅助文字 `#D1D5DB`、控件边框 `#B3FFFFFF`、分隔线 `#3DFFFFFF`。深色页面不直接沿用浅色页面的黑色正文与灰色边框。

### 2.3 间距

| Token | 数值 | 常用场景 |
| --- | ---: | --- |
| `AppSpacing.xs` | 8 | 紧凑图文、卡片内小间距 |
| `AppSpacing.sm` | 12 | 双列间距、内容页基础横边距 |
| `AppSpacing.md` | 16 | 常规内边距、卡片间距、列表边距 |
| `AppSpacing.lg` | 24 | 页面主边距、区块间距 |
| `AppSpacing.xl` | 28 | 大型区块或页脚留白 |
| `AppSpacing.xxl` | 32 | Toast 横向留白、宽松提示面板 |

标准补充：认证页左右/顶部 24、底部 20；输入框内边距 16；表单项间距 16；验证码控件间距 10；服务和设置详情页多采用 `EdgeInsets.fromLTRB(12 或 16, 12 或 16, 12 或 16, 16 或 24)`。

### 2.4 圆角、边框和阴影

| 语义 | 标准 | 使用场景 |
| --- | ---: | --- |
| 控件圆角 | 12 | 输入框、主按钮、添加车辆按钮 |
| 常规卡片圆角 | 16 | Mine 卡片、通用面板、弹窗 |
| 业务详情卡圆角 | 18 | 车辆设置、服务详情、地图/信息卡 |
| 沉浸式卡片圆角 | 20 | 购车深色卡、车型展示卡、搜索框 |
| 胶囊圆角 | 999 | 进度条、状态标签、Tab 下划线 |

- 默认描边使用 `#E5E7EB`；历史列表细分隔线可使用 `#EDEDED` 或 `#F1F1F1`。
- 卡片阴影保持轻量：Mine 卡片参考黑色 5%、模糊 14、Y 偏移 8；车辆列表卡参考黑色 4%、模糊 14、Y 偏移 8。
- 不为纯信息容器添加重阴影；深色购车卡优先用低透明度白色边线区分层级。

## 3. 页面骨架规范

### 3.1 主框架与底部导航

- 主框架固定五项：发现、精选、购车/爱车、服务、我的；通过 `IndexedStack` 保活切换。
- 图标使用 Material Icon；选中 `#4D7CFF`，未选中 `#7F7F7F`，标签统一 11 / w400。
- 未绑定车辆时第三项为黑色背景“购车 + 商店”图标；已绑定时为白色背景“爱车 + 摩托车”图标。
- 底部导航不显示水波纹、高亮和触觉反馈；页面主体仍需保留 `GrayPressable` 按压反馈。

### 3.2 二级页面导航栏

- 常规二级页使用白色 AppBar、居中标题、左侧 18px 返回图标。
- 常规详情页使用标准右进左出转场；认证链路使用淡入淡出转场。
- 页面背景为浅灰时，AppBar 允许与背景同色，但内容分组仍以白色卡片承接。

### 3.3 列表、分组与表单

- 设置类与服务详情类：浅灰页面背景、白色分组卡、18 圆角为主；内容左右 12 或 16，卡片之间 12–18。
- Mine 与通用设置：白色分组卡多使用 14–16 圆角；菜单行高度 52，左右内边距 12–14，图标盒 28×28，图文间距 10。
- 车辆设置行高度 49；复杂设置行允许 56–58，高度增加部分须用于说明文本，不能只留空。
- 输入控件默认圆角 12、内边距 16；认证页使用白色 70% 边框，浅色页使用 `AppColors.border`。

### 3.4 按钮

- 大型主操作：认证页高度 56、圆角 12；车辆/设置固定底部主按钮高度 48、圆角 10；添加车辆按钮高度 50、圆角 12。
- 车辆卡片内双按钮：高度 38、间距 10、圆角 10；主操作深灰 `#2F2F2F` 白字，次操作白底 `#D7D7D7` 边框深色字。
- 统一主色按钮使用品牌蓝时应保证白字可读；在浅灰或白底上必须有足够色彩对比。
- 禁用态采用明显降低的不透明度或灰色底，并同时禁止点击。

### 3.5 图片、图标与资源

- 资源存放于 `lib/state/`，按 `find`、`Selected`、`buycar`、`service`、`mine`、`login` 等业务目录归类。
- 新资源命名使用小写英文加下划线，例如 `vehicle_location_empty.png`；避免中文、空格、`@1x`、大小写混用。
- 本地图片使用 `Image.asset` 并指定 `fit`；网络图片必须提供本地占位或加载失败兜底。
- 服务九宫格图标规格：28×28、`BoxFit.contain`、图文间距 6、说明文字 12 / 中等字重。
- 网络头像、车辆图等必须规定加载中与失败态，失败时不可出现布局跳动。

## 4. 模块视觉基线

### 4.1 购车

- 购车首页为深色沉浸式页面，背景 `#0D0F12`，内容横向边距 16，模块间距 10/14/16/24。
- 车型横栏高度 40；选中使用白色，未选中使用约 54% 白色，下划线高 2。
- 咨询、权益、配置卡背景使用 `#14181E` 或 `#1A1F26`，圆角 20，内边距 16；标题白色，辅助文字 `white54`，边线为低透明度白色。
- 虚拟体验/爱车背景按 `#EDEDED → #F5F5F5 → #FFFFFF` 纵向渐变；页面左右 12，双列间距 12，行距 16，功能卡圆角 18。
- 爱车 Hero 与控制卡采用视觉上提叠层；车辆图片必须顶部对齐，放大后优先保留顶部主体。

### 4.2 服务

- 服务首页背景 `#F0F1FB`，主体边距 `16, 12, 16, 24`；服务九宫格和 FAQ 采用白色卡片，区块间距 18。
- FAQ 列表背景 `#F5F5F5`，搜索框白色、圆角 20、横向内边距 12、纵向内边距 10；筛选底板顶部圆角 22。
- 服务详情白卡使用圆角 18、内容 padding 14–16；正文通常 14，辅助说明 12–13。
- 地图类页面允许使用覆盖式导航和悬浮定位按钮；定位按钮直径 56，确保不遮挡底部表单或系统手势区。

### 4.3 我的、车辆与设置

- Mine 页背景 `#F5F5F5`，内容左右 16、顶部 8、底部 16，模块间距 14。
- 用户资料卡白底圆角 16，内边距左右 16、上下 14；头像 52×52；昵称 18 / w500；统计值 16 / w500；说明 12。
- Mine 快捷卡双列等宽，高 84、列间距 12、内边距 14；车辆图 56×56。
- 我的车辆列表背景 `#F5F5F5`，列表边距 16、卡片间距 16；车辆卡圆角 20、内边距 14，车辆图 140×150，电量条高度 8。
- 设置页背景 `#F5F5F5`，分组白卡圆角 14，列表行高 52；退出登录按钮深灰 `#2F2F2F`、高 48、圆角 10。

### 4.4 登录与认证

- 登录页采用全屏黑色背景图，叠加顶部轻黑、中段深黑、底部纯黑的渐变遮罩；表单锚定底部安全区。
- 内容左右 24、顶部 24、底部 20；字段间距 16。
- 输入框圆角 12，边框 `#B3FFFFFF`，输入与正文 16；验证码与登录按钮高度 56、圆角 12。
- 主文字白色，说明与协议文字 `#D1D5DB`、12；超长多语言内容使用单行跑马灯，不得破坏控件高度。

## 5. 反馈组件规格

| 组件 | 规格 | 使用规则 |
| --- | --- | --- |
| `AppLoading` | 遮罩 `#73000000`；深色面板 `#CC111111`；最小宽 128；padding 20×18；圆角 16；进度环 28 | 网络提交、关键数据加载；由引用计数统一管理 |
| `AppToast` | 默认显示 2 秒；成功、警告、错误、信息使用统一状态色 | 只提示用户可行动或已完成的结果 |
| `AppDialog` | 取消/确认按钮高 44；文字 13；对话框圆角 16 | 解绑、退出、不可逆操作必须二次确认 |
| `AppBottomSheet` | 默认安全区开启、透明外层背景 | 筛选、操作菜单、非阻断性选择 |

## 6. 落地检查清单

- 新页面是否优先使用 `AppColors`、`AppTextStyles`、`AppSpacing`、`AppRadius`？
- 页面横向边距是否统一为 12、16 或 24 中的一种主基准？
- 标题、正文、说明、指标和按钮文字是否符合字号层级？
- 卡片、输入框、按钮是否使用对应圆角，按压效果是否被正确裁剪？
- 可点击区域是否使用 `GrayPressable` 并提供重复点击保护？
- 图片是否指定 `fit`、对齐、加载态和失败兜底？
- 深色、浅色、禁用、错误等状态是否保持足够对比度？
- 长文本、多语言、SafeArea、键盘和底部导航遮挡是否已验证？
- 页面修改完成后是否在 China 与 Google Play 构建配置下分别执行静态检查？

## 7. 现状与演进

- 全局令牌已覆盖主色、基础背景、文本色、状态色、常用字号、8pt 间距阶梯和核心圆角。
- 现有业务页面仍保留历史硬编码色值与局部尺寸；本文档以“当前实际效果优先、后续新代码令牌优先”为执行原则。
- 后续若引入品牌字体、深色模式或设计系统组件，应先扩展全局 theme/token，再迁移页面，不在单页建立独立视觉体系。
