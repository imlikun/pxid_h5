# 折叠屏内屏适配 · H5 ↔ Flutter 对接文档

> 范围：发现页（Discover）折叠屏分栏。精选页分栏后续单独出，服务模块不涉及。
> 依据机型数据：2023–2026 国产四家大折叠内屏实测收敛（详见 §3.2）。
> H5 侧改动已上线（pxid_h5 `e28879f`，三远端同步）；本文档只列 **需要 Flutter 配合的部分**。

---

## 1. 🔴 现状（H5 侧已完成，Flutter 无需重复做）

发现页在 H5 侧已做掉：

- **≥600px 视口自动两栏**：左栏 = 头部 + 瀑布流错落（沿用手机版卡片规格），右栏 = 详情面板（▲上一条 / ▼下一条 连翻、默认置顶官方条、点左栏任意卡 → 右栏即时切换、**不跳页不转场**）。
- **`#app` 容器**：手机框从写死 `max-width:480px` 改成分级 —— `<600px` 仍 480px（手机态），`≥600px` 放开吃满 WebView 给到的宽度。
- **手机态零影响**：`<600px` 时右栏不渲染、左栏卡片点击照旧走原生全屏详情（`openFeedDetailNative`/`router.push`），与上线前完全一致。

结论：**H5 是"拿到多少宽度就自适应分多少"。** 854dp 直给 → 左 427 + 右 427；1337dp 若直给全宽 → 左 668 + 右 669；1337dp 若 Flutter 先扣 320 再给 1017 → 左 508 + 右 509。H5 自身只有 `600px` 这一个分栏断点，不感知"几栏"，栏数由 Flutter 给 WebView 的宽度决定。

## 2. 🟠 问题 / 卡点（H5 单侧解决不了，必须 Flutter 参与）

1. **【命门】WebView 折叠态透传宽度。** H5 靠 `window.matchMedia('(min-width:600px)')` 监听视口宽度来决定分不分栏。前提是 **Flutter 的 WebView 容器在折叠 ↔ 展开切换时，把新的 CSS 视口宽度真实传给 H5**（即 `window.innerWidth` 会变、触发 `resize`）。若 WebView 被包在固定 480/400 宽的容器里，H5 永远收不到 854/1337，本文档所有分栏都白做。
2. **三折叠（1337dp）左侧导航位。** H5 只做"左列表 + 右详情"两栏，**左侧 320dp 的竖排导航（发现/精选/服务 转 NavigationRail）不归 H5 渲染**，需 Flutter 提供；H5 只吃剩余 1017。
3. **底部 Tab 横跨整屏。** 现在底部"发现/精选/服务"是 Flutter 原生横跨底栏。1337 下三 tab 各摊 445dp、拇指跨 1300px+，Material 3 在宽 ≥600dp 时明确要求改用左侧 NavigationRail。
4. **无折叠姿态模拟器。** Chrome DevTools 只能手动输视口宽度（F12 → 宽度填 854 / 1337），没有折叠/展开/半折姿态切换；真机验证需用 Android Studio 的 Pixel Fold / 7.6" Foldable 模拟器，或实机折叠。

## 3. 🟢 怎么做（契约 + 分档 + 机型依据）

### 3.1 断点分档（H5 视角，按 WebView 实际拿到宽度）

| 拿到宽度 | 场景 | H5 布局 |
|---|---|---|
| `< 600dp` | 手机竖屏 / 折叠**外屏** / 半折 | 单栏（现状，手机规格） |
| `600–1040dp` | 大折叠内屏（854 档，14 款） | **两栏：左列表 + 右详情** |
| `≥ 1040dp` | 三折叠横握（1337 档） | **两栏（H5 吃剩余）+ 左侧 320 rail（Flutter）** |

> H5 代码里只实现"≥600 就两栏、拿到多少宽就等分多少"。第三档的左侧 rail 是 Flutter 层的事，H5 不参与。

### 3.2 机型依据（为什么断点定在 600 / 1040）

国产 4 家横向大折叠 **内屏展开态** CSS 视口宽（公式：水平物理像素 ÷ PPI × 160）：

| 品牌 | 机型 | 内屏 | 分辨率 | 视口宽 |
|---|---|---|---|---|
| 华为 | Mate X3 / X5 | 7.85″ | 2496×2224 | 835dp |
| 华为 | Mate X6 / X7 | 7.9–8.0″ | 2440×2240 | 858–859dp |
| 小米 | MIX Fold 3/4/5 | 7.9–8.0″ | 2160~2488 | 851–852dp |
| OPPO | Find N3 / N5 / N6 | 7.8–8.1″ | 2440~2480 | 852–873dp |
| vivo | X Fold 2/3/5/6 | 7.9–8.0″ | 2160~2504 | 852–870dp |

**14 款全落在 835–873dp，极差 4.6%，中位 854dp** → 一个 `600–1040` 档全吃。阔折叠 Pura X（内屏 533dp）落手机档；三折叠 Mate XT/XTs/XT2 横握 1337dp 落第三档。

### 3.3 需要 Flutter 改的三件事（按优先级）

**P0 · 透传 resize（命门，先做）**
- 确认承载 H5 的 WebView 容器宽度**随设备折叠态动态变化**（`LayoutBuilder`/`MediaQuery` 的 `width` 驱动），不要写死固定宽。
- 折叠 ↔ 展开切换后，H5 收到的 `window.innerWidth` 必须是新值（854 / 1017 / 1337），并触发 H5 的 `matchMedia change`。
- 验收：真机折叠态开发现页是单栏，展开成内屏**无需杀进程**就变两栏（H5 热切换）。

**P1 · 三折叠加左侧 320dp NavigationRail**
- `≥1040dp` 时左侧铺 320dp 竖排导航（发现/精选/服务），WebView 容器宽设为 `总宽 − 320`（1337 → 1017）。
- H5 自动把 1017 分两栏，无需 H5 侧再改。

**P1 · 底部 Tab 大屏转竖排**
- 宽 ≥600dp 时，把横跨底部 tab 改为左侧竖排（并入上面的 NavigationRail 最省事）。

### 3.4 真机联调验收清单

- [ ] 折叠态（外屏/半折，<600dp）：发现页单栏、点卡走原生全屏详情，与手机一致。
- [ ] 展开（854dp）：发现页两栏，左瀑布流错落、右详情▲▼连翻；点左卡右栏即时切换、**不跳页**。
- [ ] 三折叠（1337dp）：左 NavigationRail + H5 两栏；rail 切换发现/精选/服务。
- [ ] 折叠 ↔ 展开反复切换：布局实时重排，无白屏、无"网络有问题"重载（对照《PXID_详情页WebView重载_Flutter排查单.md》）。
- [ ] 底部 tab 在大屏下不再横跨整屏。

## 4. 🔵 最终效果（联调通过后）

- 大折叠内屏打开发现页：**一屏看两个手机宽的内容**（左刷动态、右看详情），点谁右边就出谁的详情，全程无跳转无转场。
- 三折叠横握：**左导航 + 中列表 + 右详情**三功能区并排。
- 手机竖握 / 折叠外屏：与现在完全一样，零回归。
- 折叠 ↔ 展开热切换即时生效（不杀进程）。
