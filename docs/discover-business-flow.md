# PXID App「发现」及关联业务流 · 详细业务流程方案 v1.0

> 版本：基于 v0.1 复核升级（高级产品经理 + 业务经理视角）
> 目标：输出可开发的完整业务流，划清边界、补齐漏缺、标注决策点
> 性质：**产品方案（PRD 级）**，下一步才转代码与 mock

## 1. 复核结论：v0.1 的漏缺与不合理

### 1.1 遗漏项（必须补）
1. **登录态 Gate**：发布/点赞/关注/收藏/定制提交均依赖登录，H5 经 `bridge.getToken()` 取不到 token 时的跳转与游客态可见范围未定义。
2. **跨 Tab 职能边界**：发现（内容社区+运营）、精选（电商商品）、服务（售后+门店）、购车（交易）、我的（资产）五者关系与流向未划清，"立即定制/车型/活动"在三处重复出现易打架。
3. **发布内容去向 + 审核**：发布的动态进"动态"还是"推荐"？先审后发还是先发后审？
4. **红点层级体系**：铃铛总未读、公告独立红点、动态"有新"提示三者的优先级与互斥未定义。
5. **内容种草带商品卡**：发现里"种草笔记"应可挂商品，点击跳精选商品详情/立即购买——v0.1 只提了车型标签。
6. **召回/安全类公告强提醒**：出行品类"召回通知"需强制"已知悉"动作，非普通红点。
7. **互动体系不全**：评论楼中楼、分享去向（微信/复制/系统）、收藏去哪看、关注列表管理遗漏。
8. **Push 与角标联动**：Push 点击落地页、厂商通道角标与 H5 红点同步机制遗漏。
9. **异常/空/加载态**：下拉刷新、上拉加载更多、无网络、无内容、内容下架/审核中状态遗漏。
10. **运营配置机制**：Banner/快捷入口/热门活动/公告由运营后台配置，需说明下发方式（接口 vs 静态）。

### 1.2 不合理 / 待厘清
- "动态"内部子栏（关注/推荐/附近）与顶部 3 大 tab（推荐/动态/广场）语义重叠，需明确：顶部 tab=内容形态，动态内子栏=内容来源。
- "立即定制"生成的"购车意向单"与精选"订单"、服务"工单"三者归口必须统一，否则后台混乱。
- 公告既在消息中心"系统"类、又有独立入口，需定主从，避免双份未读逻辑。

## 2. 产品定位与边界

### 2.1 五 Tab 职能
| Tab | 定位 | 核心内容 |
|---|---|---|
| 发现 | 内容社区 + 运营阵地 | UGC 动态、官方帖、种草、活动、车型展示 |
| 精选 | 电商货架 | 商品列表、商品详情、下单 |
| 购车 | 交易转化 | 车型配置、留资、下单（与"立即定制"归口） |
| 服务 | 售后与车主 | 道路救援、工单、三包、门店、指南 |
| 我的 | 用户资产 | 订单、工单、收藏、关注、设置 |

### 2.2 流向规则（关键，避免重复）
- **发现 → 购车**：发现内"立即定制/车型卡"统一跳 **购车 Tab 的定制/车型页**（不在发现内自建交易）。
- **发现 → 精选**：种草笔记挂的商品卡跳 **精选商品详情**。
- **发现 → 服务**：活动/公告里涉及售后的跳 **服务对应页**。
- 跨 Tab 跳转统一隐藏底部 TabBar（`meta.hideTabBar` 已支持），返回回到发现。

## 3. 全局前置：账号与登录态

- **登录 Gate**：进入发布/点赞/关注/收藏/定制/评论前，调用 `bridge.getToken()`。
  - 有 token → 正常；无 token → `bridge.navigateTo('login')` 或 H5 登录页，登录成功回跳原操作。
- **游客态**：可浏览推荐/动态/广场/内容详情；互动类操作触发登录引导。
- **账号体系**：以 App 统一账号为准，H5 不独立注册。

## 4. 业务流详细

### 4.1 推荐流（聚合首页）
- **定位**：运营+算法聚合信息流（官方帖/车友动态/种草/活动混排）。
- **来源**：运营后台配置流 + 算法推荐接口；Banner/快捷入口/热门活动均为配置项。
- **交互**：车型筛选（全部/P1…）+ 排序（最新/最热）；下拉刷新、上拉加载更多（分页 `cursor`）。
- **卡片点击**：按 `itemType` 分流 → 动态/种草跳 `/feed/:id`、活动跳 `/activity/:id`、商品跳精选详情。
- **埋点**：曝光、点击、停留时长。

### 4.2 动态流（关注 / UGC）
- **定位**：关注的人/车友动态时间线（强社交），与推荐最大差异在"人"维度。
- **子栏**：关注（默认）/ 推荐（算法兜底）/ 附近（LBS）—— 顶部 tab 是形态，子栏是来源，不冲突。
- **数据**：独立 `moments` 流，字段含 `author{avatar,name,userId,following}`、`images[]`、`tags[]`、`likes/comments/isLiked`、`time`、`carModel`。
- **交互**：点赞（本地 toggle + 上报）、评论跳详情、点作者进主页、关注按钮、下拉刷新/上拉加载。
- **发布去向**：用户发布 → 进入"动态-关注"流顶部 + 同步进"推荐"算法池。
- **动态红点**：顶部"动态"tab 有"新动态"时显示小红点（服务端 `hasNewMoment`），进入即消。

### 4.3 广场（车型展示 + 活动运营）
- **车型展示**：`plazaShowcase` 按 P1…P6 筛选；点击跳 **购车车型页**（非精选商品）。
- **热门活动**：卡片"立即查看"跳 `/activity/:id`；"更多"跳活动列表页。
- 活动数据运营配置，支持分页。

### 4.4 发布动态
- **入口**：顶部 ＋ → 优先 `bridge.openNative('discover.publish')`（原生发布器，体验一致）；原生不可用时降级 H5 `/discover/publish`。
- **H5 发布页**：选图/视频 → 正文 → 选车型标签 → @/话题 → 定位 → 提交。
- **审核策略**（待定）：默认**先发后审**（发布即见，违规下架）；强监管内容（召回相关）先审后发。
- **结果**：toast → 新动态插入动态流顶部 → 粉丝收到互动通知。

### 4.5 通知中心 + 红点体系（重要）
- **铃铛红点（总）** = 各分类未读之和；`>0` 显红点，多位显数字。
- **分类**：互动（赞/评/@/关注）、系统（官方公告/活动）、订单·工单、车辆（保养/救援）。
- **取数**：启动/切前台 `GET /message/unread` 拉各分类未读；进入对应分类清零。
- **公告独立红点**：发现页顶部"官方公告"入口由 `hasUnreadNotice` 驱动，与铃铛红点取并集展示（不重复计数）。
- **动态红点**：见 4.2，独立于消息中心。
- **Push 联动**：Push 点击按 `payload.type` 深链跳转；厂商角标数字 = 总未读，H5 红点与之同步。

### 4.6 内容/文章详情页（FeedDetailView 复用）
- **触发**：`/feed/:id?type=feed|activity|notice`。
- **排版**：
  1. 作者卡（头像/昵称/时间 + 关注按钮）
  2. 标题（活动/公告有）
  3. 正文富文本（图/视频/引用；`#车型#`/`@用户`/话题可点；**种草笔记内嵌商品卡** → 跳精选）
  4. 互动栏（点赞/评论/收藏/分享，底部固定）
  5. 评论区（楼中楼 + 输入栏）
  6. 相关推荐双列
- **活动**：正文上叠活动信息卡（时间/地点/报名 → `requestPurchase`）。
- **公告**：叠发布方/生效时间/置顶；召回类叠加"我已悉知"强制按钮。
- **异常**：内容下架/审核中 → 空态提示"内容不存在或已下架"。

### 4.7 立即定制（归口购车）
- **入口**：发现/服务"立即定制" → 统一跳 **购车定制页** `/buy/customize`（不在发现内自建）。
- **流程**：选车型 → 勾配置/配件 → 填联系方式 → 提交 → 生成**购车意向单**。
- **意向单状态机**：待跟进 → 已联系 → 已转化(转订单) / 已关闭。归属"购车/我的-我的意向"，不与服务工单混。
- **留资归因**：来源渠道（发现/服务）记录，供业务核算。

### 4.8 官方公告
- **类型**：版本更新、活动预告、系统维护、安全提醒、**召回通知**（强合规）。
- **入口**：
  1. **发现页顶部独立入口**（带红点，优先曝光）
  2. 消息中心"系统"分类
  3. "我的-关于-官方公告"二级入口（不单独占红点源）
- **红点**：`hasUnreadNotice` 驱动；召回类需**强提醒**（弹窗 + 必须"已知悉"才可关）。
- **已读**：个人维度，读后红点消失。

### 4.9 车型详情
- 广场车型卡 → 购车车型页（图集/配置/报价/预约试驾/立即定制入口，回流 4.7）。
- 与精选商品详情区分：车型页偏"配置选型"，商品页偏"下单购买"。

### 4.10 搜索
- 发现搜索框 → `/search` 结果页：热搜词 + 历史 + 分类 tab（内容/活动/车型/用户）+ 空态。
- 结果点击按 `itemType` 分流（同 4.1）。

### 4.11 筛选 / 排序
- 按字段真实过滤当前 tab（推荐=车型+排序；动态=子栏+时间；广场=车型），替换现字符串匹配。

### 4.12 互动体系
- 点赞/评论/收藏/关注/分享/举报：
  - 分享：`bridge` 唤起系统/微信分享，或复制链接。
  - 收藏：进"我的-收藏"列表。
  - 关注：进"我的-关注"；取关即时生效。
  - 举报：内容/评论举报 → 提交审核队列。
- 所有互动需登录 Gate（见 3）。

### 4.13 异常与边界态（全局）
- 加载：骨架屏 / loading；刷新：下拉；分页：上拉"加载更多/没有更多了"。
- 无网络：重试按钮 + 缓存兜底。
- 无内容：分类空态插画 + 引导文案。
- 内容下架/审核中：详情页空态。
