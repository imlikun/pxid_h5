# 今天干的活（2026-08-14）

就一件事：把「发现页」那套社区/内容业务流从纸面方案，真正做成了能跑的 H5 页面。

之前你跟我拍板过一份产品文档（`discover-business-flow.md`），里面列了 8 个要决策的点，你全都选了 A（基本就是「能走原生就走原生、发布先发后审、公告单独入口、召回必须点知悉」那套）。今天就是照着这份文档，一块一块把它实现了。

---

## 一、具体做了哪些

1. **登录门槛**：没登录就发布/点赞/关注，自动弹原生登录页。
2. **官方公告**：发现页顶部单独一个入口带红点；消息铃铛的红点 = 私信未读 + 公告未读（合并算，不重复）；召回类通知必须点「已知悉」才让走。
3. **内容详情页**：点进任意一条动态/文章，能看到作者、正文（车型名和 @人 可点）、九宫格图、种草商品卡、底部点赞评论收藏分享、楼中楼评论、相关推荐。
4. **动态流独立出来**：之前「动态」和「推荐」混在一起，现在拆成独立数据源，底部「发现」图标有新内容时亮红点，点进去就消。
5. **发布/点赞/关注**：加号走原生发布（H5 里给个提示兜底）；车型卡、立即定制跳原生购车页。
6. **桥接统一 + 兜底页**：把 H5 调原生的那套调用（`openNative`）格式全理顺了，补了 3 个 H5 兜底页（车型详情 / 购车定制 / 搜索），没原生环境时预览也能点通，不用等联调。
7. **推荐流不再是废文**：原来 6 条全是重复的「货运三轮」，现在换成 7 条不同类型的内容（新品、测评、种草、活动、教程、故事、技术），车型全用 pxid.com 上真实在卖的型号。
8. **积分页**：做了「我的积分」页（余额 + 积分好物列表），颜色按你给的视觉规范收了一遍，去掉了之前那个突兀的金黄色。
9. **商城接 Shopify**：商品在 H5 里只展示，点一下直接跳 Shopify 买，H5 自己不建购物车和结算（这是你定的「前台展示 + 外链成交」）。
10. **服务补漏**：在线客服那三个 tab（热门/售后查询/使用指导）原来只有一组内容、切了不变，现在按类补了；顺手修了产品说明书页左上角返回键点了没反应的 bug（漏引了个 router）。

## 二、怎么把产品补完整的（思路）

说白了就是一套干活顺序，下次还这么来：

- **先跟你对齐再写代码**：每个功能到底归原生还是 H5、审核顺序、红点算谁，全在文档里钉死，省得写着写着返工。
- **按地基往上盖**：先补数据模型和登录，再做入口红点，再详情页，再动态流，最后交互 —— 一块一块来，每块改完就 build + 提交 + 推双仓库，出事能单独回退。
- **原生能力包一层桥**：所有跳原生的动作统一走 `bridge`，格式写成 `模块/动作?参数=值`，契约记在 `INTEGRATION.md` 里，Flutter 那边照表接就行；没原生的地方用 H5 兜底页顶上，预览就能跑通整条链路。
- **内容别编太假**：车型、商品都从官网真实在售型号来，看着像真产品而不是占位废文。
- **颜色别乱写**：全走 `tokens.css` 里的令牌，遵守你那份视觉规范（之前金币用金黄就翻车了，已改品牌蓝）。

## 三、还差啥（不急，按需做）

1. **原生联调**：登录跳转、车型/定制/搜索这些，得等 Flutter 把 `window.PXIDBridge` 真实注入才能在生产环境真正跳过去；H5 这边的约定已经备好。
2. **商城孤儿页**：购物车、结算、订单那几个页面现在没人用了（商城改走 Shopify），暂时留着没删。
3. **价格红**：现在用的是业务红 `#e53935`（国内电商习惯），规范里没定义价格色，要不要统一成规范的错误红待你定。
4. **视觉全量对齐**：已做的页面有没有全部过一遍你的视觉规范，还没系统核，后续组件化时统一扫。
