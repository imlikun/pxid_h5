## 0. 结论速览

1. **必须注入两套桥**，缺一套就出 bug：
   - `window.PXIDBridge`（`isNative:true` 标记）—— H5 全部业务通信主桥。
   - `window.PXIDApp`（按《积分H5返回对接说明》）—— 仅积分页返回用 `postMessage('closeWebView')`。
2. 只注入 `PXIDApp` → H5 误判为「独立预览」（`isEmbed()=false`），`bridge.isNative()` 返回 false，发布/跳转全走 H5 兜底。
3. 只注入 `PXIDBridge` → 积分页顶部返回键关不掉 WebView，回不去「我的」。
4. 主桥需实现 **19 个方法** + **openNative 21 个标识**；其中 P0 方法 6 个须先行。

## 1. 两套桥契约

### 1.1 主桥 `window.PXIDBridge`（H5 自有契约）

- **注入时机**：WebView `load` H5 之前注入，实现对象带 `isNative: true`。
- **判定**：`isEmbed() = window.PXIDBridge?.isNative === true`。H5 据此决定走原生实现还是 H5 兜底（mock）。
- **注意**：底部 tab 已**由 H5 彻底移除**（`src/App.vue` 不再渲染 tab bar），不再依赖 `isEmbed` 切换显隐；`isEmbed` 现在只控制「原生实现 vs H5 兜底」分支与 `bridge.isNative()` 取值。
- H5 侧统一出口 `src/bridge/index.js` 已封装，业务代码只调 `bridge.xxx`，不直接碰 `window.PXIDBridge`。

### 1.2 积分子桥 `window.PXIDApp`（对方对接文档规定）

- 按《积分H5返回对接说明》：原生「我的」页用 WebView 打开 `#/points` 并隐藏原生返回键，H5 顶部返回键调 `window.PXIDApp.postMessage('closeWebView')` 关闭 WebView 回「我的」。
- 仅 `PointsView` 顶部返回键这一处使用，但缺失即积分页回不去。

### 1.3 为什么是两套

主桥是 H5 自有命名（`PXIDBridge`）；`PXIDApp` 是积分对接文档另行规定的命名。当前 H5 代码两处都依赖，Flutter 必须都注入。建议后续统一（见第 11 节）。

## 4. 登录闭环（P0 重点）

1. H5 缺 token/用户资料 → 调 `openNative('login')` → 原生拉起登录。
2. 登录成功 **`getToken` 须立即返回新 token**（H5 不刷新页面，靠 token 变化判断登录态）。
3. 同时 `getUserInfo()` 返回 `{email, nickname, avatar, carModel, token}`，任一非空即视为已登录。
4. H5 三重兜底：`bridge.getAuthToken()`（优先 `getUserInfo.token`）→ `getToken()` → `getUserInfo()`，任一命中即放行，避免「已登录仍误弹登录窗」。

## 5. 积分 WebView + `PXIDApp` 返回对接

- 原生「我的」页用 WebView 打开 `#/points`，**隐藏原生返回键**（H5 自带返回键）。
- H5 顶部返回键逻辑（`PointsView.handlePointsBack`）：
  ```js
  const app = window.PXIDApp
  if (app && typeof app.postMessage === 'function') app.postMessage('closeWebView')
  else router.back() // 独立预览兜底
  ```
- **子页** `/points/guide`、`/points/mall` 走 `router.back()`，不关 WebView（只在积分主页顶部返回键关）。
- Flutter 必须注入 `window.PXIDApp` 并实现 `postMessage('closeWebView')`。

## 6. 我的车 `carModel`（getUserInfo.carModel 第一方案）

- 第一方案：`getUserInfo().carModel` 返回真实绑定车型代号（如 `P2`，须属于在售 12 车型：`F1/F2/P1/P2/P3/P4/P5/P6/P7/P8/G1/P9`）。
- 回退方案：Flutter 未返回时，H5 用 `localStorage` 记忆（仅兜底，不当第一方案）。
- 用途：发现页「我的车」专属筛选 chip、发布页车型预选、UserProfileView 展示。
- **Flutter 必须**在 `getUserInfo` 返回 `carModel`（字段兼容：`myCar`/`vehicle`/`bindVehicle`/`boundCar` 亦可，H5 已归一）。

## 8. token 签名（后端契约）

- H5 **不再自签 deviceId**（防自签他人身份，P0-1 根因修复）。
- `getToken` 由后端 `/auth/token` 生成 HMAC 签名 token（服务端生成 deviceId）。
- Flutter 需让 `getToken` 返回**服务端签名的真实登录 token**；登录态经 `getUserInfo.token` 注入。
- 生产 `getToken` 返回真实 token；`mock` 环境返回假 token（`mock-token-standalone`），仅预览用，勿用于生产判断。

---

## 9. publish / popPage / exit

- **publish**：`discover/publish` 原生拉起发布器；H5 预览兜底路由 `/publish`。发布图文经 `pickImages`/`pickVideo` 取资源，调后端 `/feed` 落库。
- **popPage**：根页面侧滑空栈时 H5 调 `bridge.popPage()` 弹回 Flutter 原生上一级；未实现则降级「再按一次退出程序」（首次提示 toast）。
- **exit**：双按退出走 `bridge.exit()`；未实现则兜底 `openNative('app/exit')`。

## 11. 双桥统一建议 & 已知边界

- **建议（后续）**：把积分返回也统一到 `PXIDBridge`（新增 `closeWebView()` 方法），删 `window.PXIDApp` 依赖，避免两套桥命名混乱。过渡期先两套都注入。
- H5 兜底页：`vehicle/<id>`、`purchase/customize`、`search` 在 mock 下映射到同名 H5 路由；原生接入后可接管或保留降级。
- 价格红 `--price` 为国内电商习惯（涨红），若规范要统一错误红 `#D93025` 告知即可改。
- 头像/封面当前为 Unsplash 占位，接入真实用户数据后由接口替换。
- 商城孤儿页 `CartView`/`CheckoutView`/`OrderSuccessView`/`OrderListView` 暂未走通（车辆购买走 `requestPurchase`、商品走 `openShopify`/`openCheckout`），联调无需关注。
