# 发现栏目改版与验收

本次直接修改现有发现页，没有创建演示页面；精选仅同步根导航与页面背景的样式令牌，商品内容与详情购买逻辑未改。

## 三个栏目的职责

- 推荐：浏览推荐内容；保留原 Banner 和快捷入口；车型与话题标签进入相应讨论。精选标记依据实际置顶标志，不再自动把第一页前两条标为精选。
- 动态：最新动态和互动；一排展示全部、关注、附近及独立车型菜单。删除原介绍大卡片，保留动态卡片的图片、正文和互动排布。
- 广场：先找同车型讨论，再找话题和活动。车型入口先浏览讨论，再参与发布，不再点击车型就直接发帖。

## 话题与数据

讨论使用现有 `/discover` 查询参数，不新增页面或原生全屏路由。例如：

`#/discover?tab=dynamic&discussion=topic&topic=通勤骑行&from=plaza`

`#/discover?tab=dynamic&discussion=model&carModel=P2&from=plaza`

车型、话题、范围在请求中独立传递，切换条件重置分页，旧请求不能覆盖新条件。动态保留后端的新旧顺序，附近保留距离顺序；不再在客户端把置顶重新插到附近列表前面。

后端新增或扩展：

- `GET /feed?topic=...`：精确话题过滤，执行在统计与分页之前；兼容历史标签的 `#` 和外侧空白。
- `GET /feed?tab=dynamic&scope=follow`：按 token 账号的真实关注关系查询，不默认混入官方内容；未登录返回 401。旧客户端未传 scope 的接口行为保留。
- `GET /feed?scope=near&near=lat,lng`：校验坐标；无有效位置返回 400，不能用全部动态冒充附近。
- `GET /feed/topics?region=CN|BR|US`：全量公开话题统计，排除未发布、未到定时发布时间、其他地区内容及车型和内部活动标签；同一动态内重复标签只计一次。
- 现有 `POST /feed` 写入真实话题 tags；车型继续只写 carModel。发布时关联车型不改写用户绑定车型缓存。

广场的四个常用话题是内容分类入口，没有内容时允许真实空态；不虚构参与人数。其他实际话题可展开查看。活动只突出有明确日期的进行中或即将开始项，历史入口复用活动中心。广场活动请求不回落演示活动。

前端和 `server/server.js` 必须一起发布，否则旧后端不具备新增的精确话题筛选与关注范围能力。

## 原生发布入口

普通发布保留 `openNative('discover/publish')`。带车型或话题时复用该入口原有的车型 query 透传机制，传递 `carModel`、`topic`、`returnTo` 给现有 H5 `/publish`，不增加全屏白名单。

Flutter 承载页需要原样保留这三个查询参数，并继续在发布完成后调用根发现页既有 `window.__pxidOnPublished()`。H5 发布页已支持话题预选、写入 tags 和返回讨论上下文。真机参数透传、键盘、定位授权和原生关闭行为，本次没有实体设备联调，不能视为已验证。
